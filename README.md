## Português

Mocha é uma distribuição/receita de sistema Linux criada para oferecer uma experiência pronta, elegante, reproduzível e bem ajustada para diferentes tipos de uso real.

O projeto nasceu como um laboratório de sistema operacional com foco em desempenho, estabilidade, personalização visual, documentação clara e reprodutibilidade. A meta é permitir que uma máquina seja montada novamente do zero com a mesma identidade, os mesmos ajustes e a mesma base técnica validada.

### Objetivo social

O Mocha também tem uma causa.

Além de ser um projeto técnico, o Mocha nasce com uma proposta social: transformar tecnologia, documentação, testes e distribuição em uma iniciativa capaz de gerar impacto real.

As arrecadações, doações, apoios e eventuais receitas ligadas ao projeto serão direcionados para:

- manter e desenvolver o próprio projeto Mocha;
- financiar infraestrutura, testes, documentação, empacotamento e distribuição;
- apoiar a causa T21, ligada à inclusão, visibilidade e suporte às pessoas com Trissomia do 21 / Síndrome de Down.

A ideia é que o Mocha não seja apenas uma distribuição de sistema, mas também uma ponte entre tecnologia livre, acessibilidade, inclusão e impacto social.

### Versões e públicos

#### Mocha Gamer

Versão voltada para jogos, com foco em desempenho, baixa latência, Steam, Proton, ferramentas de jogos, telemetria opcional de diagnóstico, kernel e drivers validados.

#### Mocha Creator

Versão voltada para criadores de conteúdo, com foco em estabilidade, produtividade, ferramentas de criação, boa experiência visual e base reproduzível para fluxos de imagem, vídeo, áudio e trabalho criativo.

#### Mocha Escolas

Versão voltada para máquinas de escolas, laboratórios e salas de aula, com foco em instalação padronizada, manutenção simplificada, interface amigável, consistência entre várias máquinas e reaproveitamento de hardware quando possível.

#### Mocha Escritórios

Versão voltada para escritórios, atendimento, recepção e uso administrativo, com foco em produtividade, estabilidade, visual limpo, ferramentas essenciais e manutenção previsível.

### Reprodutibilidade

Um dos princípios centrais do Mocha é a reprodutibilidade.

O sistema deve poder ser remontado a partir de uma base canônica, com arquivos, receitas, documentação, scripts, políticas, assets e registros necessários para reproduzir o estado validado da máquina.

O objetivo é reduzir improvisos, evitar perda de conhecimento técnico e permitir que ajustes aprovados sejam documentados, testados, reaplicados e evoluídos de forma organizada.

### Observação sobre este repositório

A pasta canônica local do projeto pode conter caches, resultados de build, artefatos binários, cópias de estado do sistema e arquivos grandes demais para GitHub.

Por isso, este repositório público recebe a parte publicável e segura do Mocha:

- documentação;
- receitas;
- módulos;
- scripts;
- manifestos;
- políticas;
- assets visuais pequenos e médios;
- arquivos necessários para entender, testar e reproduzir o projeto.

Caches offline completos, arquivos binários grandes, cópias locais de sistema, resultados de build, segredos, chaves privadas, certificados e arquivos locais sensíveis ficam fora do GitHub.

### Créditos

O Mocha é construído sobre o trabalho de várias comunidades e projetos de software livre, incluindo:

- Linux;
- Arch Linux;
- KDE Plasma;
- Mesa;
- NVIDIA Linux;
- Steam, Proton, Wine e o ecossistema Linux gaming;
- projetos livres usados na construção, diagnóstico, empacotamento, documentação e personalização do sistema.

O Mocha existe porque esse ecossistema existe.

### Estado do projeto

O Mocha ainda é um projeto em desenvolvimento ativo.

As receitas, kernels, temas, módulos, scripts, políticas, validações e ferramentas podem mudar conforme novos testes forem feitos.

O objetivo é transformar as partes aprovadas em documentação canônica, com histórico claro do que funciona, do que foi descartado e do que ainda precisa ser validado.

### Licença e uso

Este repositório contém materiais públicos do projeto Mocha.

Partes do projeto podem depender de licenças específicas dos softwares, temas, ferramentas, pacotes e componentes utilizados. Cada componente externo mantém sua própria licença.

## English

Mocha is a Linux distribution/system recipe created to provide a ready-to-use, elegant, reproducible, and well-tuned experience for different real-world use cases.

The project began as an operating system laboratory focused on performance, stability, visual customization, clear documentation, and reproducibility. Its goal is to allow a machine to be rebuilt from scratch with the same identity, the same adjustments, and the same validated technical base.

### Social purpose

Mocha also has a cause.

Beyond being a technical project, Mocha was created with a social purpose: to transform technology, documentation, testing, and distribution into an initiative capable of generating real-world impact.

Donations, support, fundraising, and any future revenue connected to the project will be directed toward:

- maintaining and developing the Mocha project itself;
- funding infrastructure, testing, documentation, packaging, and distribution;
- supporting the T21 cause, connected to inclusion, visibility, and support for people with Trisomy 21 / Down syndrome.

The idea is that Mocha should not be only a system distribution, but also a bridge between free technology, accessibility, inclusion, and social impact.

### Versions and audiences

#### Mocha Gamer

A version aimed at gaming, focused on performance, low latency, Steam, Proton, gaming tools, optional diagnostic telemetry, validated kernels, and validated drivers.

#### Mocha Creator

A version aimed at content creators, focused on stability, productivity, creation tools, a good visual experience, and a reproducible base for image, video, audio, and creative workflows.

#### Mocha Schools

A version aimed at school machines, laboratories, and classrooms, focused on standardized installation, simplified maintenance, a friendly interface, consistency across multiple machines, and hardware reuse whenever possible.

#### Mocha Offices

A version aimed at offices, front desks, reception environments, and administrative use, focused on productivity, stability, a clean visual experience, essential tools, and predictable maintenance.

### Reproducibility

One of Mocha’s central principles is reproducibility.

The system must be rebuildable from a canonical base, with the files, recipes, documentation, scripts, policies, assets, and records required to reproduce the validated state of the machine.

The goal is to reduce improvisation, avoid the loss of technical knowledge, and allow approved adjustments to be documented, tested, reapplied, and evolved in an organized way.

### Note about this repository

The local canonical project folder may contain caches, build results, binary artifacts, system state copies, and files that are too large for GitHub.

For that reason, this public repository receives the publishable and safe part of Mocha:

- documentation;
- recipes;
- modules;
- scripts;
- manifests;
- policies;
- small and medium visual assets;
- files required to understand, test, and reproduce the project.

Complete offline caches, large binary files, local system copies, build results, secrets, private keys, certificates, and sensitive local files stay outside GitHub.

### Credits

Mocha is built on the work of several free software communities and projects, including:

- Linux;
- Arch Linux;
- KDE Plasma;
- Mesa;
- NVIDIA Linux;
- Steam, Proton, Wine, and the Linux gaming ecosystem;
- free projects used for system construction, diagnostics, packaging, documentation, and customization.

Mocha exists because this ecosystem exists.

### Project status

Mocha is still an active development project.

Recipes, kernels, themes, modules, scripts, policies, validations, and tools may change as new tests are performed.

The goal is to turn approved parts into canonical documentation, with a clear history of what works, what was discarded, and what still needs validation.

### License and use

This repository contains public materials from the Mocha project.

Parts of the project may depend on specific licenses from the software, themes, tools, packages, and components used. Each external component keeps its own license.
