# Mocha Linux

**Built to play. Built to help.**

An Arch Linux-based distribution for gaming, productivity and everyday use, with its own identity, strong performance and graphical update and recovery tools.

## What makes Mocha different

- **Strong gaming performance:** designed to compete with Windows and other gaming distributions and able to outperform them in several games and scenarios tested on the same machine.
- **Mocha LQX kernel:** based on Liquorix and prepared for low latency, responsiveness and performance.
- **Rollback to the last valid configuration:** critical updates can be reverted when a kernel, driver or essential component causes a failure.
- **Dedicated recovery partition:** an independent environment for diagnosis, repair and restoration of the main system.
- **Complete graphical interface:** updates, maintenance, recovery and component selection without forcing users to rely on the terminal.
- **Gaming-ready foundation:** Steam, Proton, GameMode, MangoHud and project-selected drivers.

## Performance without fabricated figures

Mocha Linux is being compared on the same machine with Windows and other gaming-focused distributions. It has led in several scenarios and remained competitive in the others.

Numerical results will only be published with the hardware, versions, settings and reproducible methodology used in the test. Actual performance varies by game, driver and equipment.

## Updates and recovery

Mocha is designed to give important updates a clear return path. When a kernel, driver or essential component update causes problems, the system can return to the last validated configuration.

The recovery partition complements this mechanism with an independent graphical environment for diagnosing, repairing and restoring the main installation.

## Project status

Mocha Linux is under active development. Kernels, drivers, interfaces, tools and recovery procedures continue to be tested and documented before a stable release is published.

## Repository contents

This repository contains the public and reproducible parts of the project:

- source code and interfaces;
- build scripts and recipes;
- configurations and policies;
- technical documentation;
- visual assets;
- publishable tests, reports and maintenance tools.

Local caches, secrets, private keys, full disk images and large build artifacts remain outside GitHub.
